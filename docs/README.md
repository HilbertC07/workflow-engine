## 二、每份文档里有什么

### 提示词（01 / 06 / 09）

交给 AI 编码代理的施工说明书，包含：
- 现状梳理（已有代码、已具备的接口）
- 本期要补的缺口，逐条列明
- 接口签名、页面交互流程等具体约定
- **验收标准**（含"必须在真实浏览器里实测"之类的硬性要求）

### 方案评审与回复话术（03 / 04 / 07）

用户对 AI 提交方案的**确认意见**。记录了三件事：
1. 哪些地方提得对、可以放行
2. 哪些地方有偏差、需要纠正（如字段名不符、遗漏场景）
3. 明确划定的边界（第一版不做什么）

复现"当时的判断依据"时看这些，比看最终代码更能理解设计取舍。

### 交付验收报告（05 / 08 / 10）

每个阶段的收尾文档，也是**最有实操价值的三份**。固定包含：

- 总体结论（可否验收）
- **发现并修复的问题**（含"AI 自称验证通过但实际没跑通"的案例）
- 实际验证结果（真实环境数据表格，非看代码推测）
- 用户自己需要手动验收的清单
- 给下一阶段的提醒（坑、遗留问题、注意事项）

排错时优先查这三份，多数坑已经在里面记过了。

## 三、已知的坑速查

散落在各报告里、但值得单独记住的：

| 坑 | 出处 |
|---|---|
| 前端 axios 必须带 `baseURL`，否则请求打到 Vite 自己的端口而非后端 | `08-M2交付验收报告.md` |
| LogicFlow 2.x：插件走构造参数 `plugins`（无 `use()`）、无 `getZoom()` 用 `getTransform().SCALE_X` | `08-M2交付验收报告.md`、`.cursor/rules/frontend-vue.mdc` |
| LogicFlow 锚点必须常显，否则连线拖拽中途锚点组件被卸载重建，导致"拖得动但连不出线"且无报错 | `08-M2交付验收报告.md` |
| `lf.render()` 的边数据必须显式带 `type: 'polyline'`，否则边只进数据模型不渲染 | `08-M2交付验收报告.md` |
| 依赖写进 `package.json` 但 `node_modules` 没装 —— 表现为 `TS2307` | `10-M3交付验收报告.md` |
| 会签流程里已有 1 人处理，`canWithdraw` 返回 `false` 是**正确**的，别当成 bug | `10-M3交付验收报告.md` |
| 改了后端代码必须重启服务，否则新接口返回 `{"code":500,"msg":"系统繁忙"}` | `10-M3交付验收报告.md` |

## 四、约定

- 文档按 `NN-阶段-类型.md` 编号，新增文档顺延编号
- 交付验收报告里的"实际验证结果"必须是**真实环境跑出来的**，不写"看代码推测"
- 报告要如实写明发现的问题，包括 AI 自测结论与本机实测不符的情况
