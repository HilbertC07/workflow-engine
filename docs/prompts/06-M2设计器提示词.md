## 提示词正文（从这行开始复制）

我要在 `C:\dev\workflow-engine` 下新建前端工程 `workflow-ui`，实现**可视化流程设计器**。后端引擎 M1 已完成，你只需要做前端。

### 一、目标与范围

只做**一个页面** `/designer`：左侧节点面板 → 中间画布 → 右侧属性面板，能保存流程图、能加载回来原样还原。

**不要做**：发起申请页、待办审批页、登录、路由权限、单元测试、E2E。这些是后续阶段的事。

### 二、技术栈（新建工程，依赖就这些，不要加别的）

```
vue ^3.5          vite ^6        typescript
element-plus      @logicflow/core  @logicflow/extension
axios             pinia（只存"当前用户"）
```

**不要引入**：Tailwind / UnoCSS / Sass / i18n / 其它画布库 / 状态管理之外的东西。
样式用原生 CSS + Element Plus 变量，主色沿用默认蓝。

Vite 端口固定 **5173**，不要改，也不要配 proxy（后端已配好 CORS）。

### 三、后端接口（已存在，直接用，不要改后端代码）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/workflow/definition/save` | 入参 `{code, name, graphJson}`。**`graphJson` 是 JSON 字符串，不是对象**，别直接塞对象 |
| GET | `/api/workflow/definition/{code}/latest-enabled` | 取最新启用版本，返回 `data.graphJson`（字符串） |
| GET | `/api/workflow/users` | 返回 `[{id, name, role}]`，5 个 Mock 用户 |

统一返回 `R<T> = {code, msg, data}`，`code === 0` 才是成功。
axios 封装放 `src/api/`，统一解包，`code !== 0` 时用 `ElMessage.error(msg)` 提示。

### 四、画布实现要求

1. **四个自定义节点**，继承 `RectNode`，注册到 `lf.register()`：
   `start-node`（灰）、`approval-node`（蓝）、`cc-node`（橙）、`end-node`（绿）
   节点上显示 `name`；审批节点额外显示「会签 / 或签」小标签

2. **连线**用内置 `polyline` 或 `bezier`，只允许从右侧锚点连出、左侧锚点连入

3. 插件只注册这三个：`Control`（缩放）、`MiniMap`（小地图）、`Snapshot`（导出图片）

4. **保存映射**（关键）：`lf.getGraphData()` → 后端格式
   - 节点 `type` 转成大写枚举：`start-node` → `START`、`approval-node` → `APPROVAL`、`cc-node` → `CC`、`end-node` → `END`
   - `props` 只放配置字段，**不要把 LogicFlow 的私有字段塞进去**
   - **必须带上 `x` / `y` 坐标**，否则加载回来节点全叠在原点

5. **加载映射**：后端 JSON → `lf.render({nodes, edges})`，`x`/`y` 要还原回画布坐标

6. 顶部放一个「当前用户」下拉（数据来自 `/api/workflow/users`），第一版只是存起来，不做权限

### 五、属性面板

审批节点显示：审批人类型（指定用户 / 指定角色 / 部门主管 / 发起人自选）、审批模式（会签 / 或签）、允许驳回、驳回策略、允许转办。
抄送节点显示：抄送人（多选）。开始/结束节点不显示这些字段。
改完属性要实时同步到画布上的节点文案。

「指定用户」和「抄送人」的选项来自 `GET /api/workflow/users`，**不要前端硬编码用户列表**。

### 六、校验

前端**只做**这四项快速反馈，不通过就 `ElMessage.error` 并阻止保存：
无 START / 无 END / 有孤立节点 / 无审批节点。

**不要**实现环检测、审批人可解析性这类规则——后端 `GraphParser` 已经做了，重复实现必然不一致。
保存接口返回 `code !== 0` 时，直接把后端 `msg` 显示出来。

### 七、文件结构

```
workflow-ui/
  src/
    api/            请求封装，统一解 R<T>
    types/          与后端 DTO 对齐的 TS interface（字段名必须后端驼峰）
    views/designer/ 设计器页面 + 属性面板组件
    logicflow/      四个自定义节点 + 注册 + 映射函数（保存/加载）
  package.json  vite.config.ts  index.html
```

组件全部用 `<script setup lang="ts">`，组件名大驼峰。

5. **刷新页面**，重新加载该流程 → 四个节点位置、连线、审批人配置**全部和保存前一致**（坐标不丢）
6. 用保存的流程定义去后端发起实例（我会用 curl 调 `/api/workflow/instance/start`），能正常生成待办
