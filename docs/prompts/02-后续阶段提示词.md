## M2 · 可视化流程设计器

### 提示词

```
后端引擎已经跑通了（保存定义 → 发起实例 → 审批推进 → 结束 的闭环 OK）。
现在做前端的流程设计器。

【第一步：只给方案】输出：workflow-ui 的目录结构、需要安装哪些依赖（含版本）、
自定义节点的实现方式、属性面板有哪些字段、调用后端哪几个接口。

【本次目标】
1. 在仓库根目录建 workflow-ui：Vue3 + Vite + TypeScript + Element Plus + LogicFlow
2. 页面 /designer，三栏布局：
   - 左：节点面板（开始 / 审批 / 抄送 / 结束），可拖拽到画布
   - 中：LogicFlow 画布，带缩放、小地图、清空
   - 右：属性面板，选中节点后编辑属性，改完实时更新画布上的节点文案
3. 审批节点属性：审批人类型（指定用户/指定角色/部门主管/发起人自选）、
   审批模式（会签/或签）、允许驳回、驳回策略、允许转办
4. 顶部有"保存"和"加载"：
   - 保存：调后端保存流程定义接口，入参是 .cursor/rules/approval-flow.mdc 第九节定义的 JSON 格式
   - 加载：输入 definitionId，拉取 graph_json 回显到画布
5. 保存前前端校验：无 START / 无 END / 有孤立节点 / 无审批节点 → 报错并阻止保存
6. 后端接口需要跨域支持（Controller 加 @CrossOrigin）

【明确不要做】
- 不做登录页、不做路由守卫
- 不做流程定义列表页（第一版用输入框填 definitionId 加载就够）
- 不做撤销重做、不做自动布局、不做导出 BPMN XML
- 不引入 Tailwind / Sass / 状态机库

【验收标准】
1. npm run dev 能启动，浏览器打开 http://localhost:5173/designer 看到三栏布局
2. 拖出"开始 → 部门主管审批(会签) → 抄送人事 → 结束"并连线
3. 点击保存，后端返回 definitionId，数据库 wf_process_definition 和 wf_node_definition
   各新增记录，graph_json 的格式与规则文件第九节一致
4. 用该 definitionId 加载，画布能完整还原刚才画的图
5. 故意删掉结束节点再保存，应该被前端拦住并给出中文提示

先给方案，等我确认。
```

## M3 · 发起申请 + 待办审批页

### 提示词

```
设计器已经能保存流程了。现在做业务页面，让引擎真正能被"人"用起来。

【第一步：只给方案】输出：两个页面的组件拆分、调后端哪些接口、表单字段怎么定。

【本次目标】
1. 全局：顶部一个用户切换下拉框（1001 张三 / 1002 李四 / 1003 王五 / 1004 赵六 / 1005 钱七），
   切换后所有页面的"我"随之变化
2. /apply 发起申请：
   - 选流程定义（下拉，调后端列表接口）
   - 表单第一版固定三个字段：标题、天数（数字）、事由（多行文本），存进 form_json
   - 如果流程里有"发起人自选"的审批节点，提交时要能选人
   - 提交成功后跳到 /todo 并提示实例号
3. /todo 待办审批：
   - 列表：我的待办任务（流程标题、节点名、发起人、发起时间）
   - 操作：同意 / 驳回（带意见输入框）/ 转办（选人）
   - 点开某条：展示审批时间线（调流转记录接口），按时间倒序或正序展示
   - 已处理的任务单独一个 Tab 或筛选
4. 撤回：我发起的、还没被处理的申请，可以撤回

【明确不要做】
- 不做登录鉴权（用户切换下拉框模拟即可）
- 不做表单设计器（字段写死三个）
- 不做消息通知、不做附件上传、不做审批意见表情
- 不做分页（第一版数据少，一次查完）

【验收标准】
1. 用张三发起一条请假申请（3 天）
2. 顶部切到李四，待办列表出现这条任务
3. 李四点同意 → 待办消失 → 用张三查自己发起的实例，状态是"已通过"
4. 再发起一条，切李四点驳回 → 实例状态"已驳回"，且按驳回策略回到发起人时，
   张三的待办/待重新提交里能再次看到
5. 发起一条后立刻撤回 → 实例状态"已撤回"，李四的待办里不再有它

先给方案，等我确认。
```

## M4 · 进阶能力（按需取用，别一次全上）

跑完 M3 你已经有完整闭环了。下面这些按业务需要挑，每做一个单独开一轮：

| 能力 | 提示词要点 |
|---|---|
| 条件分支 | 「连线支持 condition 条件（按 form_json 字段判断走哪条分支），需要改引擎的下一节点解析逻辑」 |
| 加签 / 转办强化 | 「审批人可以给当前节点临时加一个人，前签/后签两种」 |
| 超时自动处理 | 「xx 分钟未审批自动通过或自动驳回，需要引入定时任务（先问我要不要引入 XXL-Job 还是用 Spring @Scheduled）」 |
| 流程版本管理 | 「定义修改后生成新版本，已发起实例仍走旧版本，支持查看历史版本」 |
| 自定义表单 | 「流程定义里配置表单字段，发起页按配置动态渲染」 |
| 会签比例 | 「会签支持按比例通过，比如 2/3 同意即通过」 |
