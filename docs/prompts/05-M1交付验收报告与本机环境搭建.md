## 二、2 个必修 bug（我已在你的工程里直接改好）

### Bug 1｜START 节点 id 硬编码 → M2 做设计器后 100% NPE

`InstanceService.java` 原第 73 行：

```java
inst.setCurrentNodeKey("start_1"); // 暂写，引擎推进会修正
```

引擎推进时 `graph.node("start_1")` 会返回 **null**，接着 `switch (node.getType())` 直接空指针。

**为什么测试没发现**：测试 fixture 里的 START 节点 id 恰好就是 `"start_1"`。等 M2 接上可视化设计器，节点 id 会变成随机串，发起流程必崩。

**已改为**：解析 graph 动态取 START 节点 id，顺带修掉流水里 `nodeKey("start")` 的硬编码。

### Bug 2｜撤回缺少前置校验 → 已同意的流程还能撤回

Agent 汇报里声称"✅ 撤回判定排除抄送任务（只检查 `node_type=APPROVAL` 且 `status!=PENDING` 的任务）"，但 `ProcessEngine.cancelInstance` 里**只有 status == RUNNING 和发起人校验，没有这个检查**。

后果：李四已经点过同意，张三仍然能撤回，实例变 CANCELLED 但已存在 APPROVED 任务，状态自相矛盾。

**已补上**：撤回前统计 `node_type=APPROVAL AND status != PENDING` 的任务数，大于 0 就抛 `WF_CANCEL_NOT_ALLOWED`。抄送任务天生 COMPLETED，不参与判断。

> ⚠️ 这两处是我手改的，**本机没有 JDK 所以没能编译验证**。你装好环境第一次跑测试时留意这两处。

## 三、头号阻塞：本机缺 Java 环境

我实际探测的结果：

- `java` 不在 PATH，`C:\Program Files\Java` 等常见目录**全部不存在** → **没装 JDK**
- 项目根目录只有 `pom.xml` / `request.http` / `src` / `target`，**没有 `mvnw.cmd` 和 `.mvn/`** → 没有 Maven Wrapper
- `target/` 里的编译产物是 Agent 沙箱生成的，不是你本机编的

所以 Agent 给的 `.\mvnw.cmd test` **现在执行不了**。

## 四、环境搭建（约 15 分钟）

### 第 1 步：装 JDK 17

1. 打开 https://adoptium.net/temurin/releases/?version=17
2. 选 **Windows x64 → MSI**，下载
3. 双击安装，一路下一步，**务必勾上这两个选项**：
   - `Set JAVA_HOME variable`
   - `Add to PATH`
4. 装完**重启 Cursor（和所有终端窗口）**，否则读不到新的环境变量
5. 验证：新开终端执行 `java -version`，应看到 `openjdk version "17.x.x"`

### 第 2 步：装 Maven

1. 打开 https://maven.apache.org/download.cgi
2. 下载 **Binary zip archive**（`apache-maven-3.9.x-bin.zip`）
3. 解压到 `C:\apache-maven-3.9.x`
4. 把 `C:\apache-maven-3.9.x\bin` 加到系统 PATH
5. 验证：`mvn -version`

> 嫌麻烦的话，装 **IntelliJ IDEA Community** 也行，它内置 Maven，还能帮你自动下载 JDK。但你后续用 Cursor 开发，还是建议把命令行环境配好。

### 第 3 步：生成 Maven Wrapper（一次性）

在 `C:\dev\workflow-engine` 下执行：

```powershell
mvn -N wrapper:wrapper
```

之后项目里就会出现 `mvnw.cmd`，往后都用 `.\mvnw.cmd`，不再依赖全局 Maven。

### 第 4 步：建数据库

确认本机装了 MySQL 8（没装的话先装）。执行：

```sql
CREATE DATABASE IF NOT EXISTS workflow DEFAULT CHARSET utf8mb4;
```

`application.yml` 里默认连 `localhost:3306` / `root` / `123456`，不一致就直接改 `src/main/resources/application.yml`。
