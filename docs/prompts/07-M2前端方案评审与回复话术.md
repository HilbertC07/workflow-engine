# M2 前端方案评审与回复话术

> 评审对象：Agent 给出的 `workflow-ui/` 实现计划
> 结论：**可以开工**，但有 3 项必修、4 项建议。

---

## 一、总体评价

方案扎实，明显是读了后端源码再写的——枚举取值、`x/y` 坐标、`graphJson` 是字符串而不是对象、校验只做四项（其余交给后端）、依赖不越界，这些关键点全部到位。**这是四轮以来质量最高的一份方案。**

## 二、必修（不改会出问题）

### 1. 「指定角色」下拉没有数据源 —— 我已补好接口

你核对了 `AssigneeConfig.roleCodes`，但后端**没有任何接口暴露角色列表**。属性面板的「指定角色」选项要么前端硬编码，要么空着。

我已经补了后端接口（已编译通过，你直接用）：

- `GET /api/workflow/roles` → `R<List<ProcessRole>>`
- `ProcessRole = { code, name }`
- 当前返回：`DEPT_MANAGER 部门主管`、`GENERAL_MANAGER 总经理`

**前端要求**：「指定角色」下拉的数据必须来自这个接口，不要硬编码。选中的 `code` 放进 `props.assigneeConfig.roleCodes`。

> 后端改动文件：`ProcessRole.java`、`IdentityService.listAllRoles()`、`MockIdentityServiceImpl`、`UserController`。

### 2. 根路径必须也能渲染设计器

你打算用 `window.location.pathname === '/designer'` 判断，其他路径显示提示文字。这样直接访问 `http://localhost:5173/` 会看到一句提示，体验很差。

**改成**：`/` 和 `/designer` 都渲染 Designer，其他路径才显示提示。

### 3. 拖拽必须统一用 `lf.dnd.startDrag`

你写的是「`lf.dnd` 或直接 `lf.addNode`」——这两种不是等价的。

- `lf.addNode`：节点直接出现在画布上，**没有拖拽预览**，鼠标位置和落点无关
- `lf.dnd.startDrag`：LogicFlow 官方推荐，拖拽过程中有跟随鼠标的预览节点

**必须统一用 `lf.dnd.startDrag()`**，配合 `lf.dnd` 的 `dragstart`/`drop` 流程。

## 三、建议（不强制，但建议采纳）

### 4. `props` 白名单必须包含抄送节点的 `userIds`

你说「props 只挑白名单字段」，这条很好，但要确认白名单里包含：

| 节点类型 | 必须保留的 props 字段 |
|---|---|
| APPROVAL | `assigneeType`、`assigneeConfig`、`multiMode`、`allowReject`、`rejectStrategy`、`allowTransfer` |
| CC | **`userIds`**（抄送人列表，后端 CC 节点直接读 `props.userIds`，不在 `assigneeConfig` 里） |

### 5. `allowReject` 关掉时联动禁用 `rejectStrategy`

否则会出现「不允许驳回，但驳回策略=回到发起人」这种自相矛盾的配置，用户看不懂。

### 6. 前端四项校验里，「有且仅有一个 START」要包含「多于一个」

你写的是「无 START」。后端规则是**有且仅有一个**，两个 START 后端会拦，但反馈链路太长，前端直接拦掉更好。

### 7. 自定义节点不需要 `setViewId`

你提到「继承 RectNode + RectNodeModel，setViewId」。`setViewId` 一般只在同名节点冲突时才用。标准写法是 `lf.register({ type, view, model })` 三件套即可。

## 四、认可（按你说的做）
