## 一、本阶段在做什么

M1 做完了引擎内核（能跑通会签/或签/抄送/驳回/撤回），M2 做完了可视化设计器（能画出流程图并保存）。
**但目前没有任何页面能真正用起来**——想发起一条审批、想审批别人提交的单子，只能靠 curl 打接口。

M3 就是把这两块补上，让引擎从「能跑」变成「能用」：

| 页面 | 干什么 | 谁用 |
|---|---|---|
| 发起申请页 | 选流程 → 填标题 → 提交 → 看到流转结果 | 张三、钱七（普通员工） |
| 待办审批页 | 看到自己的待办 → 同意/驳回 → 看流转历史 | 李四、王五、赵六（审批人） |
| 我的申请页 | 看自己发起的单子进度 → 可撤回 | 普通员工 |

**本阶段结束时的验收标准**：不用 curl，全程在浏览器里点完一条完整的审批流
（张三发起 → 李四同意 → 赵六同意 → 流程通过），并且能在「我的申请」里看到流转时间线。

关键字段（照抄，别自己猜）：


### 2.2 三个必须补的后端缺口

上面接口够用，但有 **3 个明显缺口**，需要你补（都是小改动，属于本阶段范围内）：

**缺口 1｜「我的申请」没有列表接口**
现在只能按 id 查单个实例，没法查「我发起的所有单子」。需新增：
```
GET /api/workflow/instance/my?initiatorId={id}&status={可选}
→ List<InstanceVO>，按 startTime 倒序
```

**缺口 2｜「待办」不区分已办**
`/task/todo` 只返回 `PENDING`。审批人同意后就查不到这条记录了，看不到「我审批过的」。需新增：
```
GET /api/workflow/task/done?assigneeId={id}
→ List<TaskVO>（status != PENDING），按更新时间倒序
```

**缺口 3｜撤回的可用条件要在前端如实反映（暂不改后端语义）**
M1 已实现的撤回规则是（`ProcessEngine.cancelInstance`）：
- 只有**发起人本人**能撤
- 实例必须是 `RUNNING`
- **且没有任何审批人处理过**（一旦有人同意/驳回，就撤不了）

这条是刻意设计的业务约束，**本阶段不要改它**。
前端要做的是把这个规则**如实表达出来**：撤回按钮只在「发起人本人 + RUNNING + 无任何已处理任务」时可用，
其余情况置灰并给出原因提示（如「已有审批人处理」），不能让用户点了才报错。

> 判断「有没有人处理过」前端拿不到直接字段。两条路：
> (a) 调 `/instance/{id}/records`，看有没有 APPROVE/REJECT 流水 —— 准确但多一次请求；
> (b) 返回 `InstanceVO` 时补一个「是否可撤回」的布尔字段 —— 更干净，**推荐**。
> 若选 (b)，改动仅限 `InstanceVO` 加字段 + `InstanceService.getById` 填充，不得改动撤回逻辑本身。

> ⚠️ 如果实际产品上希望「走到第二步之后发起人仍可撤回」，那是**业务语义变更**，
> 不要自己决定 —— 先来问我，确认后再改 `cancelInstance` 并补测试。

### 2.3 前端现状（很重要）

M2 交付的是**没有路由**的单页应用：

- `App.vue` 里手动判断 `window.location.pathname`，`/` 和 `/designer` 渲染设计器，其他路径显示「页面不存在」
- `main.ts` 没有装 vue-router
- 已有 `stores/user.ts`（Pinia）：`users`、`currentUser`、`loadUsers()`
- 已有 `api/http.ts`（axios，baseURL 已指向 `http://localhost:8080`）
- 已有 `api/workflow.ts`（定义保存/加载、用户、角色）
- 已有 `types/workflow.ts`（类型定义）
- 设计器在 `views/designer/` 下，**保持独立，不要动它**

**本阶段第一件事就是引入 vue-router**，把 M2 预留的这个口子填上。

````
## 前端要求

  如果第一版想简化，可以只支持「流程里没有自选节点」的情况，
  但**必须在页面上给出明确提示**，不能静默失败。

**待办审批页**：
- Tab 切换「待办」/「已办」

  CC→抄送、CANCEL→撤回、FINISH→流程结束。要显示操作人和时间。
  operatorId 是数字 id，**要映射成用户名显示**（用 users 接口的数据），不能直接给用户看 1002
````

### 4.3 已知易错点（重点盯这几处）

- **切换用户后数据不刷新** —— Vue 的响应式没跟上 Pinia 变化，典型症状是切换了下拉框但列表还是旧数据

- **撤回按钮没按 `canWithdraw` 禁用** —— 已有审批人处理过了还让点，点了报错
- **去改 `cancelInstance` 的撤回限制** —— 那是刻意设计的业务约束，**不该动**。发现 Agent 动了要拦下来
