# M1 方案 v2 评审结论 + 给 Agent 的回复话术

## 一、总评

比上一版明显进步：H2 独立 DDL、COMPLETED 状态、round + current_round、CAS 防重、MAX_STEPS、版本策略、入线出线校验——上一轮提的问题基本都吸收了。可以进入写代码阶段。

**但有 5 个必修缺陷，其中 3 个会直接导致跑不起来。**

## 二、必修缺陷（动手前必须修）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | `wf_node_definition` **漏了唯一键 `(def_id, node_key)`** | 你第一版 DDL 里本来有，这一版丢了。没有它，重复保存会写入重复节点行，引擎查到下两条同名节点 | 补 `UNIQUE KEY uk_def_node (def_id, node_key)` |
| 2 | `chosenUserIds` **没有落库** | `INITIATOR_CHOOSE` 节点的审批人只在发起时存在于请求里。驳回回发起人后 `round+1` 重新生成任务时解析不到人 → 抛 `WF_APPROVER_EMPTY`，流程**永久卡死** | 实例表加 `chosen_user_ids` LONGTEXT，存 `{"approve_1":[1002,1004]}` |
| 3 | DDL 里的 `ON UPDATE CURRENT_TIMESTAMP` | 这是 MySQL 语法，**H2 不支持**，`schema-h2.sql` 若"其余一致"会直接建表失败，4 个单测全挂 | 时间一律由 MyBatis-Plus `MetaObjectHandler` 填充，两个 DDL 都去掉 `ON UPDATE CURRENT_TIMESTAMP` |
| 4 | `spring.sql.init.mode=always` + `CREATE TABLE`（无 IF NOT EXISTS） | **第二次启动就崩**（表已存在）。这是自己给自己埋的雷 | 改用 `CREATE TABLE IF NOT EXISTS` |
| 5 | H2 测试没指定 schema 位置 | `src/test/resources/application-test.yml` 若不覆盖 `spring.sql.init.schema-locations`，测试会去跑 MySQL 版的 `schema.sql`，在 H2 上报错 | 测试配置里显式写 `classpath:db/schema-h2.sql` |

## 三、需要调整 / 知情的 4 项

| # | 事项 | 结论 |
|---|---|---|
| 6 | **或签驳回语义**：你选了"全部 REJECTED 才触发" | **建议改成「任一 REJECTED 即触发」**。理由：三人或签时，甲驳回后乙再同意，流程继续——甲的驳回意见被无声吞掉，业务上很别扭。改成与会签一致的快速失败更好理解。规则文件我已按此更新，你若坚持原语义，回复时说一声 |
| 7 | **TO_INITIATOR 缺"发起人重新提交"环节** | 你的方案是驳回后直接给第一个审批节点生成新待办，发起人**还没做任何动作**，审批人就又收到一条。第一版可以接受（简化），但要知道这是取舍：严格流程应停在"待发起人修改重提"，由发起人调 resubmit 才推进。先按简化版做，流水里记好 round，前端能看到"第 2 轮" |
| 8 | `ProcessEngine` 放 `engine/executor/` | 规则里 `executor` 子包只放节点执行器，`ProcessEngine` 应在 `engine/` 包根下。挪一下 |
| 9 | `operator_id BIGINT NOT NULL` | 偏离规则（规则是 NULL 允许）。不是错误，但你必须在代码里明确每条流水的取值：SUBMIT/CANCEL=发起人，APPROVE/REJECT=该审批人，CC=被抄送人，FINISH=最后一位审批人（取不到填发起人）。已写进规则第十节 |
